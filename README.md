# trek_alfha: помощник предпринимателя в Telegram

Telegram-бот для пользователей образовательной платформы «Альфа-Курс» (Hack&Change 2026, трек 2).
Отвечает на вопросы о бизнесе по базе знаний платформы и всегда показывает, из каких материалов взят ответ.
Уточняет неясные вопросы, честно говорит, если ответа в базе нет, и учитывает профиль бизнеса пользователя.

## Что умеет сейчас

* Ответы по базе знаний (статьи, уроки бесплатных курсов, шаблоны, глоссарий, описания курсов) со списком источников и ссылками на kurs.alfabank.ru.
* Уточняющий вопрос, если запрос неоднозначный, и честный отказ, если в базе нет ответа.
* Короткая необязательная анкета о бизнесе (`/profile`): стадия, форма, налоговый режим, опыт, сфера. Ответы подстраиваются под профиль.
* Логирование событий для метрики возврата на платформу.

В работе: напоминания (разовые и повторяющиеся, налоговый календарь), рекомендации материалов по профилю.

## Архитектура

```
Telegram ──► bot (aiogram 3) ──► RAG: гибридный поиск ──► LLM (OpenAI-совместимый API)
                 │                 pgvector + полнотекст        по умолчанию Ollama
                 ▼
            Postgres 17 + pgvector
            ├─ alfa_source  выгрузка кейса (pg_restore при первом старте)
            └─ alfa_bot     пользователи, профили, индекс базы знаний, диалоги, напоминания, события
```

* `indexer` (одноразовый сервис) читает материалы из `alfa_source`, чистит HTML, режет на фрагменты по ~1200 символов и считает эмбеддинги (`bge-m3`).
* Поиск: косинусная близость эмбеддингов + полнотекстовый поиск Postgres, результаты сливаются через Reciprocal Rank Fusion.
* Если лучший фрагмент ниже порога `RAG_MIN_SIMILARITY`, бот отвечает, что в базе этого нет, не вызывая LLM.
* Платные материалы индексируются только по названию и описанию: полные тексты платных уроков не попадают ни в индекс, ни в LLM.

Схема БД: [docs/db_schema.md](docs/db_schema.md).

## Запуск

Нужны Docker с Compose и LLM-сервер с OpenAI-совместимым API.

1. Положите выгрузку кейса в `data/alfa_course_hackathon.backup` (в репозиторий она не входит).
2. Создайте `.env` из примера и укажите токен бота в `BOT_TOKEN`:
   ```bash
   cp .env.example .env
   ```
3. LLM по умолчанию — локальная [Ollama](https://ollama.com) на хост-машине:
   ```bash
   ollama pull qwen3:4b-instruct-2507-q4_K_M
   ollama pull bge-m3
   ```
4. Запуск одной командой:
   ```bash
   docker compose up --build
   ```
   При первом старте Postgres восстанавливает выгрузку, затем `indexer` строит индекс
   (около 12 тыс. фрагментов, на CPU это десятки минут; прерванная индексация продолжается с места остановки). После этого стартует бот.

Пересоздать базу с нуля: `docker compose down -v`.

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `BOT_TOKEN` | — | токен бота от [@BotFather](https://t.me/BotFather) |
| `LLM_BASE_URL` | `http://host.docker.internal:11434/v1` | OpenAI-совместимый endpoint чата |
| `LLM_API_KEY` | `ollama` | ключ API (для Ollama любой) |
| `LLM_MODEL` | `qwen3:4b-instruct-2507-q4_K_M` | модель ответов |
| `EMBED_BASE_URL`, `EMBED_API_KEY` | как у LLM | endpoint эмбеддингов |
| `EMBED_MODEL` | `bge-m3` | модель эмбеддингов (1024 измерения) |
| `RAG_TOP_K` | `6` | сколько фрагментов передавать в LLM |
| `RAG_MIN_SIMILARITY` | `0.45` | порог «в базе нет ответа» |

| `EMBED_QUERY_MODEL` | как `EMBED_MODEL` | отдельная модель для запросов (Yandex `text-search-query`) |
| `LLM_PROJECT` | — | id каталога/проекта, если провайдер требует (Yandex Cloud: folder id) |

Внешний API вместо Ollama:
* OpenAI: `LLM_BASE_URL=https://api.openai.com/v1`, `LLM_API_KEY=<ключ>`, `LLM_MODEL=gpt-4o-mini`, `EMBED_MODEL=text-embedding-3-small`.
* Yandex Cloud (AI Studio): пример в `.env.example`, модели `yandexgpt-lite` и `text-search-doc` / `text-search-query`.

При смене модели эмбеддингов индексатор сам заметит это и пересчитает векторы при следующем запуске.

### Порты

* `5433` — Postgres (проброшен наружу для отладки, внутри сети compose `db:5432`).
* Бот работает через long polling, входящие порты не нужны.

## Сценарий проверки

1. `/start`, затем `/profile`: выбрать «Уже работаю», «ИП», «УСН 6%».
2. Спросить: «Как ИП на УСН уменьшить налог на страховые взносы?» — ответ со ссылками на статьи в блоке «Источники».
3. Спросить: «Какой налог платить?» — бот задаст уточняющий вопрос.
4. Спросить о том, чего нет в базе (например, «Как вырастить кактус?») — бот честно скажет, что в базе ответа нет.

## Ограничения

* Качество формулировок зависит от модели; с локальной 4B-моделью возможны неточности, источники при этом берутся из поиска.
* Выгрузка актуальна на дату хакатона, изменения законодательства бот не отслеживает.
* Напоминания и рекомендации пока не подключены.
